# 接话 · Windows 个人微信会话助手

为每段聊天建立独立背景和记忆，结合近期消息、双方关系及你的沟通目的，先分析当前进展，再生成可编辑的回复草稿。默认先给一条回复，也可选择三条候选；你编辑、复制后回微信自行发送。

主要入口是“读取当前会话文字并分析”，通过 Windows 辅助功能尝试读取所选微信窗口公开的消息文字，不要求每次截图。**个人微信 4.1.15.13 的真实读取兼容性尚未实机验证。** 如果客户端不公开消息文字，程序会明确报错，不会自动转成截图分析或继续调用 AI。它不使用微信数据库、客户端注入或后台消息监听，也不会自动发送微信消息。

## Windows 快速开始

1. 安装官方 Python 3.10+（推荐 3.13，包含 Tcl/Tk、pip），完整解压项目后双击 `start_windows.bat`。
2. 在右上角“AI 设置”填写 API 密钥。默认使用 OpenAI API，需单独开通 API 额度；密钥仅在本次运行保留。
3. 在“记忆会话”旁点“新建”，为当前联系人起一个独立名称。在“背景/记忆”填写双方关系、已确认背景和你的沟通目标。
4. 打开对应微信聊天，点“查找微信”并选择窗口。**自己核对微信联系人与助手所选会话一致**，再勾选允许提交上下文。
5. 点击“读取当前会话文字并分析”。支持时会读取近期可见文字，合并该会话的记忆，在一次 AI 请求中返回理解摘要和回复草稿。
6. 核对右侧“AI 对上下文的理解”，编辑、复制草稿。确实在微信发出后，才点“记为已发送”。复制草稿本身不会写成已发送历史。

顶部“表达风格…”可以组合表达倾向、性格和幽默 / 玩梗 / 抽象程度，点“应用风格”后下次生成生效。右下“表情包候选…”用于浏览自己导入的图片或主动联网找候选；你看图、手动保存，再自行发到微信，助手不发送表情包。

第一次使用时，助手不知道安装前的历史。可以先复制近期聊天，标注“我 / 对方”，通过“导入复制文字”或直接粘贴导入，再确认分析；这些文字会进入所选命名会话的近期记忆。以后补充新内容时，会保留已有历史并合并重叠片段。详细步骤见 [Windows 使用说明](docs/WINDOWS.md)。

## 记忆、速度与数据

- 不同名称的会话分别保存背景和历史。“临时会话（不记忆）”仅处理本次输入，不能用于直接读取并分析。
- 默认记忆只保留本次运行。可在“背景/记忆”明确启用本机明文保存；Windows 文件位置为 `%LOCALAPPDATA%\JieHua\conversations.json`。开关适用于所有命名会话，关闭并保存会删除该文件，保留本次运行中的记忆。
- “清空本次内容”只清除输入和草稿。删除已记录历史或整个会话，需要在“背景/记忆”分别使用“清空历史”或“删除会话”。密钥和截图不写入会话记忆，模型推测也不会自动变成背景事实。
- 默认“先给 1 条（较快）”，以文字输入减少重复识图，并限制输出长度。界面会显示等待和生成用时；没有真实 API 速度基准，不承诺固定响应秒数。模型、网络和上下文长度都会影响等待时间。
- 提交生成时，会向你配置的 AI 服务发送本次输入及所选会话的背景、历史。服务商保留请求的政策另行适用。

## 表达风格和表情候选

“表达风格…”把多个维度分开设置：我的表达倾向为中性 / 偏男性化 / 偏女性化；性格表达另选自然、温柔体贴、直率爽快、理性克制、活泼外向、慢热内敛或俏皮毒舌。幽默、玩梗和抽象各有 0–3 四级，也可直接用“稳妥日常”“轻松有梗”“抽象搞怪”预设。表达偏好不代表实际性别，也不会据此推断对方身份。

命名会话各自保留风格组合；退出后继续保留仍需开启原有的本地会话保存。AI 会结合场合调整表达，严肃或难过的聊天不应机械堆梗。适合配图时，同一次回复请求会给出简短表情主题和标签；没有合适建议时可为空。

“表情包候选…”支持明确选择本地 PNG、JPEG、GIF、WebP 导入并加标签，每次最多 20 张、每张 10 MB。导入会将副本持久保存在 `%LOCALAPPDATA%\JieHua\memes`，与会话记忆保存开关独立；删除表情只删库里的副本。

也可以主动联网从 [ChineseBQB 公开资源](https://github.com/zhaoolee/ChineseBQB) 获取候选，无需另配密钥。候选匹配使用主题、标签、分类及文件名，不是对图片内容的视觉语义识别；不向图库上传原始聊天，只请求公开资源包。网络图片在本次窗口中暂存，保存或加入本地库须由你操作。预览会显示来源，GIF 预览首帧，保存保留原始动图字节。来源或网络不可用时会报错，不会假装已经取得图片。

## 开发与配置

```sh
python3 bootstrap_desktop.py --setup-only
.venv/bin/python desktop.py
```

上述为 Linux/macOS 命令；Windows 使用 `.venv\Scripts\python.exe`。桌面 UI 需要图形显示和 Tk；直接读取微信文字仅支持 Windows。启动器优先使用 Python 3.13，使用固定依赖 Pillow 12.0.0，Windows 另安装 uiautomation 2.0.29 和 comtypes 1.4.17。

启动器会检查 pip 完整性。遇到 `pip._vendor.rich._extension` 缺失，会完整备份旧 `.venv` 后重建一次；不删除 `.env`。新环境仍无法运行 pip 时，应通过官方安装程序修复 Python，不关闭 TLS 或包校验。

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `CHAT_API_KEY` | API 密钥，亦可在桌面设置中临时填写 | 无 |
| `CHAT_API_BASE` | HTTPS OpenAI 兼容接口 | `https://api.openai.com/v1` |
| `CHAT_MODEL` | 模型 | `gpt-4.1-mini` |

接口需支持 `/chat/completions`、JSON 输出及 `max_tokens`。文字流程可使用只支持文字的模型；截图备用流程需要模型支持 `image_url`。会话记忆保存开关只管理文字资料和风格，不保存 API 设置；明确导入的表情图片由独立本地库管理。

## 验证

```sh
.venv/bin/python -m unittest discover -s tests -v
node --check static/app.js
```

无显示器时桌面 UI 测试会明确跳过；使用虚拟显示器才能执行。测试覆盖会话隔离、历史合并、已发送确认、本地保存和删除、单条及三条输出、消息区域读取范围、超时与失败处理，以及损坏 pip 的备份重建。模型和 Windows 原生读取使用替身，不证明真实 API 或微信版本兼容性。

## 可选入口

截图导入仍保留为备用：系统截图或微信截图 → 导入剪贴板截图 → 预览框选 → 确认分析。图片只用于本次生成，不会自动转成长期文字记忆。

原网页版通过 `python3 server.py` 启动，默认仅监听回环地址的 8000 端口（`HOST` / `PORT` 可覆盖），保留手动文字和图片输入；桌面会话管理不在网页版中。手机使用需要另行部署带身份认证的 HTTPS 入口，不要把开发服务器直接暴露到公网。网页不会直接读取 iPhone 微信。
