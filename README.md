# 接话 · Windows 个人微信会话助手

为每段聊天建立独立背景和记忆，结合近期消息、双方关系及你的沟通目的，先分析当前进展，再生成可编辑的回复草稿。新版将聊天输入和回复并排显示，常用操作集中在主界面，截图及窗口设置收进“更多工具”。默认先给一条回复，也可选择三条候选；你编辑、复制后回微信自行发送。

可点“截取微信”：为单独打开的微信聊天窗口框选一次消息区，之后自动截图，在本机用 Windows OCR 转成文字，再交给 AI 生成草稿。这条流程不向模型上传图片，不要求 GLM 等模型具备读图能力。也保留“窗口文字”方式，通过 Windows 辅助功能尝试读取消息列表。**个人微信 4.1.15.13 的直接文字读取及 Windows 原生截图/OCR 仍需实机验证。** 程序不访问微信数据库、不注入客户端，也不会自动发送微信消息。

## Windows 快速开始

1. 安装官方 Python 3.10+（推荐 3.13，包含 Tcl/Tk、pip），完整解压项目后双击 `start_windows.bat`。
2. 在右上角“AI 设置”填写 API 密钥。默认使用 OpenAI API，需单独开通 API 额度。
3. 在“当前会话”旁点“新建”，为当前联系人起一个独立名称。关系、已确认背景可在“背景与记忆”补充；沟通目标直接写在主界面。
4. 打开对应微信聊天，**自己核对微信联系人与助手所选会话一致**，点“开启自动辅助”。只有一个可用微信窗口时自动选择；有多个窗口时会让你选择一次，也可在“更多工具”中指定。
5. 支持时会读取近期可见文字，合并该会话记忆，返回理解摘要和回复草稿；之后定时检查新内容。只需分析一次时，使用“一键分析当前聊天”。
6. 核对右侧理解摘要，编辑、复制草稿，或自行启用“生成后复制”。确实在微信发出后，才点“记为已发送”。复制本身不会写成已发送历史。

顶部“表达风格”可以组合基础语气、表达倾向、性格和幽默 / 玩梗 / 抽象程度。已经生成草稿时，点右侧“换风格重写”，选好后点“应用并重新生成”，直接复用当前聊天和会话记忆，无需重新截图；请求中保留原稿，重写失败也保留原稿。只保存偏好可用“应用风格”。调整风格时会暂停自动辅助，后台正在进行的旧读取结果不会覆盖重写。右下“找个表情”用于浏览自己导入的图片或主动联网找候选；你看图、手动保存，再自行发到微信，助手不发送表情包。

第一次使用时，助手不知道安装前的历史。可以先复制近期聊天，标注“我 / 对方”，通过“粘贴聊天”或直接粘贴导入，再确认分析；这些文字会进入所选命名会话的近期记忆。以后补充新内容时，会保留已有历史并合并重叠片段。详细步骤见 [Windows 使用说明](docs/WINDOWS.md)。

## 截图识字与自动截图

1. 将微信聊天单独打开，核对助手中的会话名称，点主界面的“截取微信”。
2. 选择目标窗口，只框选近期消息区一次，排除联系人列表和输入框。首次预览会将输入法浮条等遮挡部分标灰，不再因为消息区外的小浮窗而拒绝打开预览；灰色部分不能加入选区。点“绑定并开始分析”，左侧显示识别文字，之后自动生成草稿。
3. 将微信与助手并排摆放，保持选区无遮挡，点“开启自动辅助”，默认每 10 秒截图识字。移动窗口可以继续使用，缩放、遮挡或关闭时会暂停；重新框选用“更多工具 → 重选区域”。

自动截图检查的是你绑定的消息选区。微信输入框里的输入法工具条、消息区外的任务栏或其他浮层，不会影响这个选区；真正盖住消息时仍会暂停。截图前后观察到的遮挡区域会在初次预览中遮去，已确认全局透明度为零的窗口不算遮挡。

“截取微信”会重新刷新窗口列表，避免沿用拉出独立聊天之前的主窗口。找不到微信时，会提供“手动绑定聊天窗口”：点“开始选择”，在 3 秒内点击独立微信聊天窗口，让它位于最前方；助手恢复后预览所选窗口，核对并框选消息区，再开始分析。也可从“更多工具 → 手动绑定”进入。手动选择不依赖微信进程名称，程序不会验证所选应用是否为微信，需你核对预览；只绑定你点选的这个窗口和区域，窗口及选区不跨运行保存。之后开启自动辅助可继续复用绑定。

**已有系统截图时，点“粘贴截图”，无需重新截取微信窗口。** “截取微信”和“分析微信窗口”会重新采集实时窗口，因此需要检查窗口的位置和遮挡；“粘贴截图”及“打开截图文件”只处理导入图片，不依赖微信是否在屏幕内。打开手动截图、文件或系统截图工具时，会先暂停定时采集，避免实时窗口的提示干扰图片分析。

手动截图后，点主界面的“粘贴截图”，框选消息区，在确认界面直接选择：

- **大模型看图并分析**：把确认的选区作为 `image_url` 交给当前模型，一次请求返回截图转写、会话理解和回复草稿。转写文字显示在左侧，并合并进当前命名会话的记忆；后续使用文字继续分析，不重复上传原图。需要模型和中转接口都支持图片输入，模型列表中存在某个名称并不证明它能看图。
- **本机识字并分析**：在 Windows 本机转成文字，再交给当前模型，不上传图片，适合只有文字能力的接口。

图片已保存成文件时，用“更多工具 → 打开截图文件”，同样可以选择以上两种方式。模型未返回可读转写时会提示，不显示该次草稿、不将该次图片记成已经读懂。转写可能有错字或说话者不明，请核对。自动辅助仍使用本机识字，手动选择大模型看图不会启用定时上传图片。

本机 OCR 依赖 Windows 10/11 的系统识字组件和语言功能，优先使用已安装的中文识字语言。没有可用语言、截图为空或识字失败时会提示，不提交旧内容给 AI。本机识字的截图只在本机内存和子进程管道中处理，识别文字按原有会话记忆选项管理。“大模型看图”则会向你配置的 AI 服务上传选区；更多工具中的“粘贴截图给大模型”也可直接进入此流程。

## 自动辅助

自动辅助默认每 10 秒检查一次选定微信窗口；可在“更多工具”中改为 5、10、20 或 30 秒。截图模式复用已绑定区域，相同像素跳过 OCR，相同识别文字不再请求 AI；读取和生成不会并发堆积。OCR 可能有错字，动态表情或识别误差也可能影响变化判断，请核对左侧文字。状态栏显示暂停原因，可随时暂停；退出后不会自动重启。采集方式会记住，窗口与截图区域每次运行重新绑定。

请保持微信停留在允许读取的聊天，切换联系人前先暂停。程序绑定助手所选会话和微信窗口；窗口变化、读取失败或消息上下文完全不连续时暂停。**这些检查不能可靠识别同一微信窗口内切换联系人**，不能代替你核对会话。

自动辅助只生成草稿。自动复制为独立可选项，不会点击微信或发送文字、图片；表情包仍由你看图、保存并发送。完整操作见 [Windows 使用说明](docs/WINDOWS.md)。

尚未处理的草稿会保留；有新内容时先等待，你复制草稿或明确记为已发送后再继续生成。即使启用自动复制，之后对草稿的编辑也会受到保护。

## 记忆、速度与数据

- 不同名称的会话分别保存背景和历史。“临时会话（不记忆）”仅处理本次输入，不能用于直接读取并分析。
- 默认记忆只保留本次运行。可在“背景与记忆”明确启用本机明文保存；Windows 文件位置为 `%LOCALAPPDATA%\JieHua\conversations.json`。开关适用于所有命名会话，关闭并保存会删除该文件，保留本次运行中的记忆。
- “清空”只清除输入和草稿。删除已记录历史或整个会话，需要在“背景与记忆”分别使用“清空历史”或“删除会话”。密钥和截图不写入会话记忆，模型推测也不会自动变成背景事实。
- 默认“先给 1 条（较快）”，以文字输入减少重复识图，并限制输出长度。界面会显示等待和生成用时；没有真实 API 速度基准，不承诺固定响应秒数。模型、网络和上下文长度都会影响等待时间。
- 提交生成时，会向你配置的 AI 服务发送本次输入及所选会话的背景、历史。服务商保留请求的政策另行适用。

## 表达风格和表情候选

“表达风格”把多个维度分开设置：我的表达倾向为中性 / 偏男性化 / 偏女性化；性格表达另选自然、温柔体贴、直率爽快、理性克制、活泼外向、慢热内敛或俏皮毒舌。幽默、玩梗和抽象各有 0–3 四级，也可直接用“稳妥日常”“轻松有梗”“抽象搞怪”预设。表达偏好不代表实际性别，也不会据此推断对方身份。

命名会话各自保留风格组合；退出后继续保留仍需开启原有的本地会话保存。AI 会结合场合调整表达，严肃或难过的聊天不应机械堆梗。适合配图时，同一次回复请求会给出简短表情主题和标签；没有合适建议时可为空。

“找个表情”支持明确选择本地 PNG、JPEG、GIF、WebP 导入并加标签，每次最多 20 张、每张 10 MB。导入会将副本持久保存在 `%LOCALAPPDATA%\JieHua\memes`，与会话记忆保存开关独立；删除表情只删库里的副本。

也可以主动联网从 [ChineseBQB 公开资源](https://github.com/zhaoolee/ChineseBQB) 获取候选，无需另配密钥。候选匹配使用主题、标签、分类及文件名，不是对图片内容的视觉语义识别；不向图库上传原始聊天，只请求公开资源包。网络图片在本次窗口中暂存，保存或加入本地库须由你操作。预览会显示来源，GIF 预览首帧，保存保留原始动图字节。来源或网络不可用时会报错，不会假装已经取得图片。

## 开发与配置

```sh
python3 bootstrap_desktop.py --setup-only
.venv/bin/python desktop.py
```

上述为 Linux/macOS 命令；Windows 使用 `.venv\Scripts\python.exe`。桌面 UI 需要图形显示和 Tk；直接读取微信文字仅支持 Windows。启动器优先使用 Python 3.13，使用固定依赖 Pillow 12.0.0，Windows 另安装 uiautomation 2.0.29 和 comtypes 1.4.17。

启动器会检查 pip 完整性。遇到 `pip._vendor.rich._extension` 缺失，会完整备份旧 `.venv` 后重建一次；不删除 `.env`。新环境仍无法运行 pip 时，应通过官方安装程序修复 Python，不关闭 TLS 或包校验。

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `CHAT_API_KEY` | API 密钥，亦可在桌面设置中临时填写 | 无 |
| `CHAT_API_BASE` | HTTPS OpenAI 兼容接口 | `https://api.openai.com/v1` |
| `CHAT_MODEL` | 模型 | `gpt-4.1-mini` |
| `CHAT_ALLOW_HTTP` | 仅设置为 `1` 时允许配置的 HTTP 接口；默认不允许 | `0` |

接口需支持 `/chat/completions`、JSON 输出及 `max_tokens`。文字与本机识字流程可使用只支持文字的模型；“大模型看图”需要模型和接口支持 `image_url`。不能仅凭 `GLM-5.3-Flash` 等中转模型名称判断视觉能力，应向服务商确认对应模型的图片输入支持。会话记忆、桌面设置和表情收藏分别管理。桌面设置位于 `%LOCALAPPDATA%\JieHua\settings.json`；密钥默认只在本次运行使用，Windows 可明确选择通过当前用户的 DPAPI 加密保存，不以明文写入设置文件。

自定义接口在“AI 设置”中填写地址、模型 ID 和服务商密钥。地址只填到 `/v1` 等前缀，不附加 `/chat/completions`。HTTP 地址需要明确勾选“允许此 HTTP 地址”：密钥和聊天会明文传输；更换地址会重置开关。HTTPS 的证书校验保持开启。“获取模型列表”（旧称“测试接口”）只验证模型列表连通，可用于校正模型名大小写，不能证明生成或看图可用；未提供 `/models` 的服务也可保存后直接尝试生成。

“测试文字生成”发送一段虚构的会议确认对话，实际调用当前模型，核对会话摘要及回复草稿的返回结构。“测试图片识别”则生成一张六位随机识别码的合成图，识别码不出现在文字提示中；只有读对识别码并完成与截图分析相同的返回流程才提示通过。两种测试各发送一次生成请求，可能按服务商规则计费；不发送你的聊天、会话记忆或剪贴板图片，也不把测试内容写入会话。一次通过不保证持续稳定，图片基本测试也不能保证所有中文聊天截图都识别正确。大模型看图失败时，完整提示也会显示在右侧“AI 理解”，可选中复制。详见 [Windows 使用说明](docs/WINDOWS.md)。

若文字生成正常、只有看图间歇提示拒绝访问，请分别运行上述两种测试。HTTP 403 表示接口或中间代理拒绝了该次请求，不能仅凭状态码断定密钥无效、模型不支持图片或服务已停机。请向服务商核对 `image_url`（包括 base64 图片）、模型权限、图片大小限制、来源 IP 和访问规则。生成提示会明确区分文字请求和图片请求；程序不读取并展示可能含敏感内容的上游错误正文。确认前可以使用“本机识字并分析”或自动辅助：在 Windows 本机把截图变成文字，继续使用当前接口生成草稿，无需向模型上传图片。

连接失败会显示具体类别：DNS、证书或 TLS、请求超时、连接被拒绝、连接中断、网络不可达及网关状态码。保留 HTTPS 校验、当前系统代理与重定向限制，不自动重发生成请求。提示不回显底层异常中的地址、凭据、聊天内容或响应正文；实际服务状态仍需结合运行电脑上的结果判断。

“返回格式不对”表示已收到响应，但没有解析出要求的回复结构。程序支持标准 JSON、Markdown 包裹的 JSON、文本内容块和已解析的结构化对象，仍会核对回复、会话摘要及截图转写字段；思考过程不会作为最终回复。请求明确使用非流式输出，不自动重发修复格式。

“AI 设置 → 输出上限”默认 4096 tokens，可在 512–16384 之间选择并保存在本机。旧版单条文字请求只有 400 tokens，带思考模型可能在最终 JSON 输出前耗尽预算。新版会明确提示被截断、仅有思考内容、JSON 语法错误或缺少必要字段；出现截断时可改为服务商支持的更高上限再手动重试。上限不要求模型写满，费用和思考 token 的计算以服务商规则为准；回复本身仍要求简短。

## 验证

```sh
.venv/bin/python -m unittest discover -s tests -v
node --check static/app.js
```

无显示器时桌面 UI 测试会明确跳过；使用虚拟显示器才能执行。测试覆盖会话隔离、历史合并、已发送确认、本地保存和删除、单条及三条输出、消息区域读取范围、选区移动/尺寸/遮挡检查、本机 OCR 管道、自动辅助去重与暂停、桌面设置，以及损坏 pip 的备份重建。模型、Windows 原生采集、OCR 和密钥加密使用替身，不证明真实 API、Windows 识字效果或微信版本兼容性。

## 可选入口

系统截图或微信截图 → 主界面“粘贴截图” → 确认消息选区 → 选择“大模型看图并分析”或“本机识字并分析”。两种方式都会显示识别文字，图片本身不会写入会话记忆。

原网页版通过 `python3 server.py` 启动，默认仅监听回环地址的 8000 端口（`HOST` / `PORT` 可覆盖），保留手动文字和图片输入；桌面会话管理不在网页版中。手机使用需要另行部署带身份认证的 HTTPS 入口，不要把开发服务器直接暴露到公网。网页不会直接读取 iPhone 微信。
