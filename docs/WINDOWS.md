# Windows 10/11 使用说明

## 安装和打开

1. 从 [python.org](https://www.python.org/downloads/windows/) 安装 Python 3.10 或更新版本，推荐 3.13，保留 Tcl/Tk、pip 和 Python Launcher 组件。
2. 将 ZIP 完整解压到可写文件夹，关闭旧助手，双击新文件夹内的 `start_windows.bat`。不要直接在压缩包里运行。
3. 首次启动会检查项目 `.venv` 和 pip，安装固定版本的 Pillow 12.0.0、uiautomation 2.0.29、comtypes 1.4.17；以后复用正常环境。无须管理员权限。
4. 在右上角“AI 设置”填写密钥。默认是 OpenAI API / `gpt-4.1-mini`，需要单独开通 API 额度，ChatGPT 订阅不包含 API 额度。密钥仅在本次运行保留，不要发到聊天里。

这是需要 Python 的桌面脚本包，不是独立 EXE，不需要部署网站。

## 先建立会话背景和记忆

1. 在“记忆会话”旁点“新建”，输入联系人或聊天的名称。不同联系人使用不同名称，避免混用历史。
2. 在“背景/记忆”填写双方关系、已确认的背景和沟通目标。例如：“同事；正在协调下周会议；希望确认时间，但不要替我承诺周末有空。”只写你确认的事实。
3. 点“保存资料”。默认这些记忆只留在本次运行；是否退出后继续保存，可在同一窗口明确选择。
4. 初次使用时，先补充必要的过去聊天。可以在微信复制最近消息，点“导入复制文字”或直接在左侧粘贴，标清“我 / 对方”，再勾选确认并点“分析并生成”。

助手不知道安装前或从未导入的历史。背景由你填写；历史来自你确认分析的文字和明确标记的已发送内容，不会凭空取得微信的全部记录。聊天文字进入会话记忆后，即使生成请求失败，也仍保留在该会话中，便于重试。

## 一键分析当前微信会话

1. 在助手选择对应的“记忆会话”。不要使用“临时会话（不记忆）”。
2. 打开电脑版微信，进入对应聊天，保持窗口还原并显示近期消息。
3. 回到助手点“查找微信”，从下拉框选中允许读取的窗口。
4. **核对微信当前联系人与助手的记忆会话一致**，勾选“确认会话匹配并允许提交上下文给 AI”。程序不能可靠核实联系人身份，切换微信聊天后也要切换助手会话。
5. 点“读取当前会话文字并分析”。成功时会读取当前消息列表公开的文字，清除本次附加图片，合并所选会话的背景和历史后调用 AI。
6. 核对右侧“AI 对上下文的理解”，再编辑回复。读到的文字也可在左侧修改后重新分析；无法确定发言者时，不要把模型推断当成事实。
7. 点“复制回复”，回微信粘贴并自行发送。确实发出后，再回助手点“记为已发送”并确认。这一步只是补充会话历史，不会代你发消息。

文字读取最多尝试约 8 秒，只读取可访问消息区域的近期可见条目，最多 100 条、12000 字，不自动翻页。它不读取联系人列表、微信数据库或后台消息，也不注入客户端。

**你使用的微信 4.1.15.13 尚未完成实机兼容性验证。** 是否能直接读到文字，取决于微信是否向 Windows 辅助功能公开消息列表。当前读取器只接受明确命名的消息列表；没有可读列表、列表为空或目标不明确时会停止并提示，不提交 AI，也不会自动退回截图分析。

如果这个版本不提供消息文字，当前的一键读取就无法完成。可先复制近期聊天文字导入，验证会话记忆和回复效果；不能把这一步描述为已经自动接入微信。

## 回复速度和显示内容

默认模式为“先给 1 条（较快）”，也可选“生成 3 条候选”。AI 对上下文的理解和草稿在同一次请求中生成，结果完整返回后显示，不是流式逐字输出。

文字流程不再每次上传图片，近期历史和生成长度也有限制。界面会显示等待时长及生成用时，但没有真实 API 速度基准，不能承诺几秒完成。网络、模型、输入长度和图片都会影响速度。可先使用简短文字、单条回复模式比较实际等待时间。

截图导入本身不需要密钥；“读取当前会话文字并分析”包含后续 AI 调用，因此需要先配置有效密钥。

## 保存、查看和删除记忆

“背景/记忆”显示当前会话的背景、目标及已记录历史。不同会话分别保存，模型生成的候选草稿和复制操作不会自动写成已发送事实。

- **只在本次运行记忆**：默认行为，退出后丢失未保存的会话资料。
- **本地保存开关**：勾选后点“保存资料”，将所有命名会话的文字资料以明文保存到 `%LOCALAPPDATA%\JieHua\conversations.json`。重新打开助手时可以恢复；请按自己的设备使用情况决定是否开启。
- **关闭本地保存**：取消勾选并点“保存资料”，会删除应用保存的记忆文件，但本次运行中的会话仍在。
- **清空本次内容**：只清除当前输入、截图和草稿，保留会话的关系、目标和历史。
- **清空历史**：删除当前会话已记录的聊天，保留背景、关系和目标；如果开启本地保存，也会更新磁盘文件。
- **删除会话**：删除该会话的背景和全部历史；其他会话不受影响。

历史有长度上限，会保留近期内容并合并重叠导入片段，并非完整微信档案。截图和 API 密钥不写入会话记忆，也不会自动从截图提取并长期保存事实。生成时会把当前输入和所选会话的记忆提交到配置的 AI 服务；服务商的数据保留政策另行适用。

## 备用：导入截图

当文字读取不支持时，可自行决定是否使用图片：

1. 在微信打开聊天，按 **Win+Shift+S**，或在助手点“系统截图（备用）”，框选消息区域。
2. 从任务栏回助手，点“导入剪贴板截图”。若没有图片，先打开截图并按 Ctrl+C。
3. 在预览中拖动框选允许分析的区域，点“确认使用选区”。截图缩略图出现表示已附加成功；左侧不会自动填入识别文字。
4. 核对所选会话、文字和图片，填写意图，确认后点“分析并生成”。不需要的旧文字或图片应先清除。

本次最多附加一张图，最长边缩小到 2000 像素。图片只用于本次生成；如果希望某个事实进入后续记忆，应在“背景/记忆”中填写，或把相应文字导入。小屏幕上可以滚动左侧输入区，确认和生成按钮固定在底部。

## 常见问题

- **没有可读取的消息列表**：先确认已打开具体聊天、窗口未最小化；仍不支持时，说明此微信画面没有公开读取器需要的文字。复制文字导入即可继续测试记忆功能，不需要关闭系统保护或修改微信。
- **“未能采集到窗口内容”，但微信明明已打开**：这是备用窗口截图得到空白或纯色画面，不是没找到微信。部分微信画面不能用这种方式截图；可改用手动系统截图。它与文字读取是两种不同的尝试。
- **AI 不知道以前聊过什么**：检查是否选对命名会话，确认相关文字确实导入过，并在“背景/记忆”查看记录。没有开启本地保存时，重启后不会保留；从未导入的历史也不会自动出现。
- **复制了草稿，却没记到“我已发送”**：这是为了避免把未发送的内容当成事实。只有实际发送后，明确点“记为已发送”才记录。
- **`No module named 'pip._vendor.rich._extension'`**：pip 缺少内部文件，程序尚未进入微信功能。新启动器会将旧 `.venv` 完整保留为 `.venv.backup-时间-编号`，在最终路径重建一次，不删除 `.env` 或旧文件。
- **新环境的 pip 仍无法运行**：运行 python.org 官方 Python 安装程序选择 Modify/Repair，或重新安装包含 pip、Tcl/Tk 的 Python 3.13。单独 `ensurepip --upgrade` 可能因版本相同而跳过缺失文件；不要关闭 TLS 或包校验。
- **文字读取组件缺失**：关闭助手，再运行新版本的 `start_windows.bat`。它会检查并安装 Windows 专用依赖；不要覆盖正在运行的旧文件。
- **网络安装失败**：确认可访问 `pypi.org`、`files.pythonhosted.org`，保留错误信息后重试。网络失败不触发重复重建；已有环境被占用时先关闭相关助手和终端，启动器不会强行结束进程。
- **生成报错或一直等待**：检查 API 密钥、额度、模型和网络。默认 OpenAI API 与 ChatGPT 订阅分别计费；文字流程需要 JSON 输出和 `max_tokens`，图片备用还需视觉输入支持。

可用 `py -3.13 bootstrap_desktop.py --setup-only` 单独准备环境。环境备份目录默认忽略，不提交 Git。

## 验证范围

环境准备、会话记忆、提示组装、输出解析和桌面交互有自动化测试。Windows 辅助功能文字读取使用替身验证范围、超时和失败分支，真实 API 及微信 4.1.15.13 仍需实机验证。测试成功不代表已经取得个人微信官方消息接口。
