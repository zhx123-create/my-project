# Windows 10/11 使用说明

## 安装和打开

1. 从 [python.org](https://www.python.org/downloads/windows/) 安装 Python 3.10 或更新版本，推荐 3.13，保留 Tcl/Tk、pip 和 Python Launcher 组件。
2. 将 ZIP 完整解压到可写文件夹，关闭旧助手，双击新文件夹内的 `start_windows.bat`。不要直接在压缩包里运行。
3. 首次启动会检查项目 `.venv` 和 pip，安装固定版本的 Pillow 12.0.0、uiautomation 2.0.29、comtypes 1.4.17；以后复用正常环境。无须管理员权限。
4. 在右上角“AI 设置”填写密钥。默认是 OpenAI API / `gpt-4.1-mini`，需要单独开通 API 额度，ChatGPT 订阅不包含 API 额度。密钥默认仅在本次运行保留；Windows 可主动勾选记住密钥，由当前 Windows 用户加密保存。不要把密钥发到聊天里。

这是需要 Python 的桌面脚本包，不是独立 EXE，不需要部署网站。

## 先建立会话背景和记忆

1. 在顶部“当前会话”旁点“新建”，输入联系人或聊天的名称。不同联系人使用不同名称，避免混用历史。
2. 在“背景与记忆”填写双方关系、已确认的背景和沟通目标。例如：“同事；正在协调下周会议；希望确认时间，但不要替我承诺周末有空。”只写你确认的事实；也可直接在主界面填写本次沟通目标。
3. 点“保存资料”。默认这些记忆只留在本次运行；是否退出后继续保存，可在同一窗口明确选择。
4. 初次使用时，先补充必要的过去聊天。可以在微信复制最近消息，点“粘贴聊天”或直接在左侧粘贴，标清“我 / 对方”，检查内容后生成。

助手不知道安装前或从未导入的历史。背景由你填写；历史来自你确认分析的文字和明确标记的已发送内容，不会凭空取得微信的全部记录。聊天文字进入会话记忆后，即使生成请求失败，也仍保留在该会话中，便于重试。

## 自动读取并填入微信输入框

先在助手选择与目标微信聊天对应的会话、人设及沟通意图，配置好 AI。之后常用操作只需要：

1. 单独打开该微信聊天，点一下**空白输入框**。
2. 按 **Ctrl + Alt + R**，松开按键后等待。程序自动读取消息；读不到文字时，在本机自动截图识字，再调用文字模型生成一条回复，不需要手动截图或框选。
3. 回复填写到原来的输入焦点后，你核对内容，再自行按发送。等待期间请保持键鼠和输入焦点不动。

也可以在助手点“一键填入微信”，助手会缩小；在3秒内点击独立微信聊天的空白输入框即可。它重新取得你实际点选的窗口，不依赖此前下拉框中的旧目标。再次按 Ctrl+Alt+R 或回助手点“取消填入”，可取消后续操作。成功时不抢回微信焦点；失败时恢复助手，完整提示在“AI 理解”中可复制。

它先尝试读取当前窗口的消息列表，不支持时自动截取这个窗口、遮去被浮窗盖住的区域并使用 Windows 本机 OCR。不会截取整个桌面，也不需要当前 AI 模型看图；上传的是识别文字、所选会话背景、历史和人设。请使用独立聊天窗口，避免主微信窗口里的其他联系人被包含进识别内容。识字、发言者和聊天身份仍需你核对；切换微信联系人时也要切换助手会话。

输入框支持 ValuePattern 时直接填写，并核对其文字；不要求微信提供发送按钮。没有该能力时，程序向你明确选择的输入焦点提交 Unicode 字符，保留剪贴板，不使用全选、删除或 Enter。此回退路径只能向光标处追加，无法保证检测出原有文字，也无法确认微信是否接受输入，所以请先点空白输入框，最后查看微信中的结果。

Unicode 输入依赖系统当前焦点，检查无法完全消除检查后瞬间切换的竞态，因此等待和填入期间请不要操作键鼠或切换应用。

窗口关闭或变化、键鼠操作、焦点移动、生成期间检测到新聊天文字时，会取消本次填入。它不打开图片或语音，不能保证检测到所有非文字消息变化。填写失败或只填入部分文字时不自动重试，已生成的草稿保留在右侧。填入不会点击发送，不会记录成已发送历史；你实际发送后仍可手动“记为已发送”。“生成后复制”的偏好不改变此流程的剪贴板。

Ctrl+Alt+R 若被其他软件占用，助手会提示，仍可使用按钮。微信与助手都应以普通权限运行，无需管理员权限。该功能使用原有依赖，没有增加安装步骤；云端模拟验证不能代替 Windows/微信4.1.15.13实机验证。

## 一键分析当前微信会话

如果微信不能直接公开消息文字，可使用下面的截图识字流程，入口为“截取微信”。它从可见消息区在本机识字，不依赖微信消息列表，也不要求 AI 模型具备读图能力。

1. 在助手选择对应的“当前会话”。不要使用“临时会话（不记忆）”。
2. 打开电脑版微信，进入对应聊天，保持窗口还原并显示近期消息。
3. **核对微信当前联系人与助手所选会话一致**，点“一键分析当前聊天”。只有一个可用微信窗口时自动选择；有多个窗口时会让你选择一次，也可在“更多工具”的下拉框中指定。
4. 成功时会读取当前消息列表公开的文字，清除本次附加图片，合并所选会话的背景和历史后调用 AI。程序不能可靠核实联系人身份，切换微信聊天后也要切换助手会话。
5. 核对右侧理解摘要，再编辑回复。读到的文字也可在左侧修改后重新生成；无法确定发言者时，不要把模型推断当成事实。
6. 点“复制回复”，回微信粘贴并自行发送；也可启用“生成后复制”，省去复制按钮。确实发出后，再回助手点“记为已发送”并确认。这一步只是补充会话历史，不会代你发消息。

文字读取最多尝试约 8 秒，只读取可访问消息区域的近期可见条目，最多 100 条、12000 字，不自动翻页。它不读取联系人列表、微信数据库或后台消息，也不注入客户端。

**你使用的微信 4.1.15.13 尚未完成实机兼容性验证。** 是否能直接读到文字，取决于微信是否向 Windows 辅助功能公开消息列表。当前读取器只接受明确命名的消息列表；没有可读列表、列表为空或目标不明确时会停止并提示，不提交 AI，也不会自动退回截图分析。

如果这个版本不提供消息文字，当前的一键读取就无法完成。可先复制近期聊天文字导入，验证会话记忆和回复效果；不能把这一步描述为已经自动接入微信。

## 定时检查并生成草稿

截图模式先点“截取微信”，选择单独聊天窗口并框选消息区一次；具体步骤见下方截图说明。窗口文字模式仍使用微信辅助功能读取器。

选好命名会话、配置 AI 并打开对应微信聊天后，点“开启自动辅助”。程序默认每 10 秒检查一次当前选定窗口，有新内容时生成草稿；无需每条消息再点读取和生成。在“更多工具”可将间隔改为 5、10、20 或 30 秒。

状态栏会显示检查、等待和暂停原因。“暂停自动辅助”始终保留，可以在读取或等待 AI 时点击。暂停后，仍在进行的读取或生成结果会被忽略；重新开启需要你操作，重启助手也不会自行开启。

- 相同内容不会反复调用 AI；只是在消息列表中回看旧内容，也不会当作新消息。检查与生成按顺序处理，不会积压多个并发请求。
- 当前草稿未处理时，新内容先等待，不覆盖你的修改；复制草稿或明确记为已发送后，才继续生成。启用自动复制后再次编辑草稿，也会重新等待你处理。
- 自动辅助绑定所选命名会话及微信窗口。切换助手会话、窗口变化、窗口关闭或读取失败时会暂停；消息上下文完全不连续时，也会先暂停，避免继续合并陌生内容。
- **保持微信停留在已允许的聊天；切换联系人前先暂停。** 同一个微信窗口内的联系人身份仍无法可靠核实；窗口和上下文检查不能保证识别所有聊天切换。
- “窗口文字”模式依赖微信公开消息列表，失败时会暂停；“截图转文字”模式需你先明确绑定可见消息区，不会从窗口文字模式暗中切换到截图。

“生成后复制”为可选项，默认关闭。打开后会用新草稿替换剪贴板文字，方便你回微信粘贴；复制不等于已经发送。自动辅助不点击微信、不自动发文字或图片，表情包仍需你手动保存和发送。

## 自定义角色与自动回复机器人（实验）

1. 选择命名会话，在主界面选定一个微信聊天窗口。只对这个窗口运行，不自动切换联系人。
2. 点顶部“聊天机器人”，填写角色描述、口头禅和几句示例。比如“虚拟聊天搭子，简短、机灵、轻微吐槽”，示例“行，那我负责精神支持”。也可使用预设再修改；“表达风格”的各维度仍有效。
3. 在“允许自动回复什么”写明范围，例如“只接日常闲聊；问到我实际行程、邀约或资料中没有的事实时不回复”。规则由模型判断，不是保证零误判的关键词过滤器。示例句只提供表达方式，不作为真实经历或身份。
4. 只想改善现有草稿时，点“只保存人设”即可，后续普通生成和看图分析都会使用它。人设随会话记忆保存，默认不落盘。
5. 要运行机器人，填写**微信聊天顶部显示的名称**，核对当前消息确实是“左侧对方 / 右侧自己”，先选择“试运行（只生成，不发送）”。点“开始机器人”后先建立基线，不回复启动前的旧消息。让对方发一条新消息，观察左侧“我 / 对方”标注及右侧回复。
6. 若当前版本控件支持且试运行符合预期，可暂停后重新进入，明确选择“自动发送文字”并启动。运行状态和允许发送不保存，每次运行重新开启。默认每5秒读取，合并连续消息后判断是否回复；发送至少间隔10秒。后台检查和生成串行，不堆积请求。
7. “暂停机器人”始终可点击。暂停后在途 AI 结果不再启动发送；如果已进入发送阶段，点击发送可能已经发生，请核对微信，程序不会重发。输入框有你的草稿、标题/进程变化、消息不连续、控件无法确认、API失败或发送结果不确定时均暂停。

此机器人仅支持微信公开 UI Automation 标题、消息列表、输入框 ValuePattern 和发送按钮 InvokePattern 的窗口；按你确认的左右布局保守判断消息方向。**微信 4.1.15.13 尚未完成实机发送验证；若只有截图识字可用，当前机器人发送路径不能使用。** 缺少控件会明确暂停，不能把它描述成已经接通。长气泡横跨两侧、复杂布局、图片/语音等无法确认方向的条目不触发自动回复；它不自动听语音、点开图片、翻页或切换聊天，也不使用全局模拟键盘、剪贴板或盲点坐标发送。

建议使用单独打开的聊天窗口；运行时不要切换微信联系人或手动编辑微信输入框。标题名称匹配不是微信账号 ID 校验，不能识别所有同名联系人或竞态切换。窗口及消息检查不能代替保持目标聊天不变。

自动模式会把所绑定会话的新文字、背景、人设及历史交给所配置的 AI 服务，生成请求可能计费。仅在观察到自己的消息出现在聊天中、且输入框清空时记为已发送；发送按钮调用本身不代表已经成功。失败后先手动核对，再决定是否重新开启。表情候选仍由你手动保存和发送。

## 记住设置与 API 密钥

接口地址、模型、自动复制开关和检查间隔保存在 `%LOCALAPPDATA%\JieHua\settings.json`。开启会话记忆的本地保存后，助手也可恢复上次选择的已有会话；自动辅助的运行状态不保存。

API 密钥默认仅用于本次运行。Windows 的“AI 设置”提供明确的记住密钥选项，使用当前 Windows 账号的 DPAPI 加密后保存；文件中不写明文密钥。取消记住并保存会移除已保存的加密密钥，当前运行仍可继续使用已填写的值。该功能不支持在其他 Windows 账号或其他系统间迁移密钥；解密失败时应重新填写。

桌面设置、会话文字记忆和表情收藏彼此独立。关闭会话文字保存不会删除设置中的加密密钥或表情图片；如不再需要记住密钥，请在“AI 设置”单独取消。

## 自定义接口与 HTTP 地址

1. 在“AI 设置”填写服务商提供的接口地址、模型 ID 和密钥。接口需要支持 OpenAI 兼容聊天格式；模型名称以该接口提供的 ID 为准。
2. 地址填写到 `/v1` 等前缀，例如 `http://your-api-host/v1`；不要附加 `/chat/completions`，程序会自行补全。复制地址时末尾的空白会去除。
3. 使用 HTTP 时，明确勾选“允许此 HTTP 地址”。**HTTP 会明文传输密钥和聊天内容**，请确认信任地址及网络；服务商提供有效 HTTPS 地址时可优先使用。更换地址会清除此开关，HTTPS 证书校验不会关闭。
4. 点“获取模型列表”（旧称“测试接口”），获取可用模型列表；不会提交聊天或生成回复。当前名称仅大小写不一致时，会按服务返回值校正；其他情况可从模型下拉框选择。列表可达只证明该查询成功，不代表看图可用。
5. 点“测试文字生成”，用虚构的会议确认对话实际验证当前模型的摘要及回复返回结构，再点“保存并继续”。文字测试不上传你的聊天或图片，也不写入会话。截图还要求模型支持图片输入，模型列表可访问也不代表所有生成格式都受支持。

要验证“大模型看图并分析”，点“测试图片识别”。它会调用当前 AI，可能计费，只发送程序生成的随机识别码图片，不发送聊天、会话记忆或剪贴板图片。正确读出识别码并返回所需结构才算通过。失败时依据完整提示区分图片输入、认证、网络及返回格式问题；通过基本测试也不能保证每张中文聊天截图都识别正确。

文字和图片测试分别只发送一次生成请求，均可能计费，一次成功不代表接口持续稳定。如果只有看图间歇返回 HTTP 403，而文字生成正常，请让服务商核对模型的 `image_url`（含 base64 图片）支持、图片大小和权限限制、来源 IP 及访问规则。403 表示接口或中间代理拒绝了请求，单凭它不能确认具体原因；“获取模型列表”成功也不能排除图片请求限制。可以先选择“本机识字并分析”：截图在 Windows 本机转成文字，当前 API 只接收文字；自动辅助同样使用这条流程。

部分中转接口不提供 `/models`，测试出现此提示时仍可保存后尝试生成。认证失败、模型不存在、生成格式不兼容是另外的问题，需要依据实际返回结果区分；不要把密钥发到聊天里。HTTP 授权随对应地址保存，API 密钥仍遵守上面的独立保存选项。看图失败的完整提示会显示在右侧“AI 理解”，可以选中复制。

## 回复速度和显示内容

默认模式为“先给 1 条（较快）”，也可选“生成 3 条候选”。AI 对上下文的理解和草稿在同一次请求中生成，结果完整返回后显示，不是流式逐字输出。

文字流程不再每次上传图片，近期历史和生成长度也有限制。界面会显示等待时长及生成用时，但没有真实 API 速度基准，不能承诺几秒完成。网络、模型、输入长度和图片都会影响速度。可先使用简短文字、单条回复模式比较实际等待时间。

截图导入本身不需要密钥；一键分析及自动辅助包含后续 AI 调用，因此需要先配置有效密钥。

## 组合自己的表达风格

在顶部点“表达风格”，分别选择：

- **我的表达倾向**：中性、偏男性化、偏女性化。这是写作偏好，不代表实际性别，也不用于推断聊天对象的身份。
- **性格表达**：自然、温柔体贴、直率爽快、理性克制、活泼外向、慢热内敛、俏皮毒舌。
- **幽默、玩梗和抽象程度**：每项独立设置为 0–3，0 表示不刻意使用，3 表示强度较高。

也可选择“稳妥日常”“轻松有梗”“抽象搞怪”预设，再单独调整。点“应用风格”后，下次生成生效，已有草稿不会自动改写。命名会话分别记住各自的组合；需要退出后恢复时，仍要在“背景与记忆”开启本地保存。严肃、道歉或难过的话题会按场合收敛玩梗，不保证每条回复都带梗。

## 表情包候选：先看图，再手动保存和发送

适合配图时，模型会在生成回复的同一次请求中附带表情主题和简短标签；不合适时可以没有建议，不会为了凑数强行推荐。右下角点“找个表情”可浏览图片。主题和标签用于匹配分类、文件名及本地标签，**不是理解每张图片内容的视觉搜索**；候选是否合适仍需你看图判断。

本地图片可以通过文件选择框明确导入，支持 PNG、JPEG、GIF、WebP，每次 1–20 张、每张不超过 10 MB。你可以添加标签，方便之后根据主题挑选。图片会复制到 `%LOCALAPPDATA%\JieHua\memes`，以后打开助手仍可浏览；这与会话文字的本地保存开关独立。删除本地表情只删除库副本，不删除当初导入的原图。

也可明确点击联网查找，从 [ChineseBQB](https://github.com/zhaoolee/ChineseBQB) 的公开分类包中获取图片，不需要额外图库密钥。助手只请求固定公开资源包，不把原始聊天发给图库；按主题、标签、分类或文件名选择候选，匹配结果不代表图片一定符合当时情境。

网络候选只在本次窗口内存中暂存。需要保存到指定位置或加入本地收藏时，由你主动点击相应操作；浏览或联网查找本身不等于收藏。候选会显示来源链接。GIF 在界面中只预览首帧，手动保存时保留原始动图文件，不会自动转为静态图片。

所有表情都由你手动保存，再自行在微信选图发送；助手不会代发、点击微信发送按钮，或把浏览图片记成已发送消息。公开源和网络可能不可用，失败时会提示，不会显示伪造的下载结果。

## 保存、查看和删除记忆

“背景与记忆”显示当前会话的背景、目标及已记录历史。不同会话分别保存，模型生成的候选草稿和复制操作不会自动写成已发送事实。

- **只在本次运行记忆**：默认行为，退出后丢失未保存的会话资料。
- **本地保存开关**：勾选后点“保存资料”，将所有命名会话的文字资料以明文保存到 `%LOCALAPPDATA%\JieHua\conversations.json`。重新打开助手时可以恢复；请按自己的设备使用情况决定是否开启。
- **关闭本地保存**：取消勾选并点“保存资料”，会删除应用保存的记忆文件，但本次运行中的会话仍在。
- **清空本次内容**：只清除当前输入、截图和草稿，保留会话的关系、目标和历史。
- **清空历史**：删除当前会话已记录的聊天，保留背景、关系和目标；如果开启本地保存，也会更新磁盘文件。
- **删除会话**：删除该会话的背景和全部历史；其他会话不受影响。

会话风格随上述会话资料保存或删除。表情库是另一份明确导入的本地收藏，关闭文字记忆保存或删除会话不会删除这些图片；请在表情候选窗口管理库副本。

历史有长度上限，会保留近期内容并合并重叠导入片段，并非完整微信档案。截图和 API 密钥不写入会话记忆。截图识别出的文字会合并到所选命名会话，持久保存仍由本地记忆开关决定；模型推断不会写成用户确认的背景事实。生成时会把当前输入和所选会话的记忆提交到配置的 AI 服务；服务商的数据保留政策另行适用。

## 截图识字：自动截取单独聊天窗口

若提示“没有找到微信窗口”，请用弹出的“手动绑定聊天窗口”，或“更多工具 → 手动绑定”。点“开始选择（3 秒）”后助手会缩小，在 3 秒内点击你单独打开的微信聊天窗口，使它保持在最前面。助手恢复后会显示所选窗口的预览；确认确实是你允许读取的聊天，再框选消息区。此方式只绑定你点选的窗口，不依赖微信进程名称，也不会自动验证所选应用是微信。绑定后可继续开启自动辅助；关闭、标题变化或被其他窗口遮挡仍会暂停。

1. 在微信中将需要的聊天单独打开，确认助手所选命名会话与当前联系人一致。
2. 点主界面“截取微信”，从多个微信窗口中选中目标。初次会将选定窗口置于前方并显示本地预览。
3. 只框选近期消息区，排除联系人列表、输入框及无关内容，点“绑定并开始分析”。首次预览会把输入法浮条等遮挡部分标灰，消息区外有浮条也可以打开预览；不能把灰色区域加入选区。识别文字显示在左侧，再交给当前模型生成草稿，截图不交给模型。
4. 将微信与助手并排摆放，保持选区无遮挡，再点“开启自动辅助”。之后复用该选区定时截图；像素未变时跳过 OCR，识别文字未变时跳过 AI。
5. 移动聊天窗口可以继续使用；窗口尺寸改变、最小化、遮挡或关闭时会暂停。重新框选用“更多工具 → 重选区域”，切换采集方式也在更多工具中。

采集方式会保存，窗口及选区仅在本次运行绑定。截图识字需要 Windows 10/11 的系统 OCR 和可用语言功能，优先使用已安装的中文识字语言；缺少组件或语言时会明确提示，可先粘贴聊天文字继续。没有识别到文字时请放大微信字体、只选近期消息。OCR 可能有错字和分行误差，不自动确定说话者，请核对左侧结果。真实 Windows 截图/OCR 兼容性仍需在你的设备验证。

## 手动截图与截图文件

已有系统截图时，请用“粘贴截图”或“打开截图文件”。“截取微信”及“分析微信窗口”（旧版称“截图识字／一键截图识字”）会重新截取实时窗口，检查窗口位置；它们不会使用你的系统截图。导入图片不需要微信位于屏幕内，也不需要保持窗口可见。打开手动截图入口后，定时采集会先暂停；取消预览也不会自动恢复采集。

当文字读取不支持时，可自行决定是否使用图片：

1. 在微信打开聊天，按 **Win+Shift+S**，或展开助手的“更多工具”点“系统截图”，框选消息区域。
2. 回助手点主界面“粘贴截图”，框选消息区，然后选择“大模型看图并分析”或“本机识字并分析”。前者把选区上传给当前模型，一次返回转写、理解和草稿；后者先在本机识字，再把文字交给 AI。两者都会在左侧显示文字。
3. 如果截图保存成了文件，使用“更多工具 → 打开截图文件”，也可选择以上两种方式；复制文件本身不等于把图片放进剪贴板。
4. 如有识别错字，修改左侧内容，再点“用编辑内容生成”。识字失败时不会提交旧内容，也不会把未知图片当作已经读懂。

“大模型看图”需要当前模型和中转接口都支持 `image_url` 图片输入与 JSON 输出，仅凭 `GLM-5.3-Flash` 这个名称无法确认。如果模型不支持图片，需要向服务商选择支持视觉的模型，或使用“本机识字并分析”。模型未返回可读转写时会提示，不展示该次草稿、不写入该次图片内容。更多工具中的“粘贴截图给大模型”可以直接进入模型看图流程。

本机识字将截图最长边缩至 2000 像素，在本机内存与子进程管道中处理。大模型看图会上传你确认的选区，成功后移除原图附件，之后可用转写文字继续分析；文字可能有错字，说话者需要核对。识别文字按所选会话的记忆选项管理，图片不写入会话记忆。自动辅助仍使用本机识字，不会因手动选择大模型看图而开始定时上传图片。

## 生成后切换语言风格

在右侧“回复工作台”点“换风格重写”，选择自然、温柔、幽默、简洁或正式的基础语气，再组合性格、表达倾向和幽默 / 玩梗 / 抽象程度，点“应用并重新生成”。它使用左侧当前聊天、原有背景和会话记忆，不会重新采集微信，也不会把旧草稿当成已经发送。请求期间及失败时保留旧稿，成功后替换。只想保存选择而暂不重写时，点“应用风格”。

自动辅助读取期间也可以打开风格设置；进入设置会先暂停自动辅助，并忽略在途的旧读取结果，避免重写时被后台采集打断。调整完成后，如需定时检查，可再点“开启自动辅助”。

## 常见问题

- **“AI 返回的内容格式不对”**：这表示已经收到响应，但没有解析出规定的回复结构。新版支持带 Markdown 代码块的 JSON、文本内容块和结构化对象，并会具体提示被截断、只返回思考内容、JSON 不合法或缺少字段。默认输出上限已从旧版单条文字的 400 tokens 调整为 4096；若明确提示“被截断”，可在“AI 设置 → 输出上限”选择服务商支持的 8192 等额度，再手动重试。它不是自动重发请求，也不会把思考过程或普通解释误当成聊天草稿。提高上限可能影响等待与费用，按实际服务规则计算。

- **“无法连接 AI 服务”**：先在“AI 设置”核对实际接口地址，再点“获取模型列表”。列表也连接失败时，优先检查地址、端口、网络、系统代理或向服务商确认状态；列表可达仍不代表生成或图片输入可用，可分别尝试一段文字和“测试图片识别”。新版会区分 DNS、证书、超时、拒绝连接、连接中断，以及 502 / 503 / 504 等服务状态。错误提示不会包含密钥或上游响应正文；连接失败不会自动重发生成请求。请复制完整提示供排查，不要发送密钥。没有具体网络错误和你的电脑测试结果，不能直接断定中转服务已经停机或模型不支持图片。

- **微信与助手已并排，仍提示选区被挡住**：旧版首次绑定会检查整个窗口，底部输入法浮条也可能触发。新版先显示遮挡部分已标灰的预览，只需框选消息区，排除底部输入框和灰色部分。绑定后只检查消息选区，消息区外的浮窗不影响采集；盖住消息的浮窗仍需移开。需要重绑时使用“更多工具 → 重选区域”。

- **已经用系统截图，却提示“移出屏幕”**：这条提示来自实时窗口采集，发生在调用 AI 之前，不能据此判断模型能力。请点“粘贴截图”，导入已有图片后选择“大模型看图并分析”或“本机识字并分析”。新版会在导入时暂停实时采集，并忽略此前采集任务的过期提示。

- **没有可读取的消息列表**：先确认已打开具体聊天、窗口未最小化；仍不支持时，说明此微信画面没有公开读取器需要的文字。复制文字导入即可继续测试记忆功能，不需要关闭系统保护或修改微信。
- **“未能采集到窗口内容”，但微信明明已打开**：这是备用窗口截图得到空白或纯色画面，不是没找到微信。部分微信画面不能用这种方式截图；可改用手动系统截图。它与文字读取是两种不同的尝试。
- **AI 不知道以前聊过什么**：检查是否选对命名会话，确认相关文字确实导入过，并在“背景与记忆”查看记录。没有开启本地保存时，重启后不会保留；从未导入的历史也不会自动出现。
- **自动辅助暂停了**：先看状态栏原因。窗口关闭、读取失败、切换会话或上下文不连续都会暂停；核对微信当前聊天与助手会话后，再主动开启。增加检查频率不能解决微信不公开消息文字的问题。
- **复制了草稿，却没记到“我已发送”**：这是为了避免把未发送的内容当成事实。只有实际发送后，明确点“记为已发送”才记录。
- **`No module named 'pip._vendor.rich._extension'`**：pip 缺少内部文件，程序尚未进入微信功能。新启动器会将旧 `.venv` 完整保留为 `.venv.backup-时间-编号`，在最终路径重建一次，不删除 `.env` 或旧文件。
- **新环境的 pip 仍无法运行**：运行 python.org 官方 Python 安装程序选择 Modify/Repair，或重新安装包含 pip、Tcl/Tk 的 Python 3.13。单独 `ensurepip --upgrade` 可能因版本相同而跳过缺失文件；不要关闭 TLS 或包校验。
- **文字读取组件缺失**：关闭助手，再运行新版本的 `start_windows.bat`。它会检查并安装 Windows 专用依赖；不要覆盖正在运行的旧文件。
- **网络安装失败**：确认可访问 `pypi.org`、`files.pythonhosted.org`，保留错误信息后重试。网络失败不触发重复重建；已有环境被占用时先关闭相关助手和终端，启动器不会强行结束进程。
- **生成报错或一直等待**：检查 API 密钥、额度、模型和网络。默认 OpenAI API 与 ChatGPT 订阅分别计费；文字流程需要 JSON 输出和 `max_tokens`，图片备用还需视觉输入支持。

可用 `py -3.13 bootstrap_desktop.py --setup-only` 单独准备环境。环境备份目录默认忽略，不提交 Git。
